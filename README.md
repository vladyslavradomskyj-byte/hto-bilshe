# Хто більше? — робочий прототип MVP

Багатокористувацька браузерна гра-аукціон за ТЗ v3.1. Сервер на Python без сторонніх залежностей, клієнт — mobile-first HTML/JS.

## Запуск

```bash
py server.py
```

Відкрийте http://localhost:8787. Друзі в тій самій Wi-Fi відкривають адресу, яку сервер друкує при старті (`http://<IP>:8787`); Windows може попросити дозволити доступ у брандмауері. Код кімнати й посилання-запрошення видно в лобі.

Тести:

```bash
py -m unittest discover -s tests -v
```

```bash
py tests/http_smoke.py
```

(другий — на запущеному сервері: два гравці, одночасні ставки, SSE).

## Що реалізовано

- **Кімнати й лобі:** вхід без реєстрації (захищена cookie-сесія, на сервері лише хеш токена), код із 6 символів і посилання `/r/КОД`, готовність, боти 5 рівнів, глядачі, передача ролі організатора вручну й автоматично через 120 с офлайну, повернення на своє місце після оновлення сторінки.
- **Налаштування:** тема, 8/15/20 лотів, $20–100, 15/25/45 с, складність, стиль ведучого, ліміт гравців, показ ваг, глядачі. На старті параметри фіксуються в партії.
- **Аукціон:** серверний таймер; продовження до 5 с після ставки, але не більше ніж на +30 с; заборона перебивати власну ставку; резервування, звільнення й списання з append-only журналом; ідемпотентні ставки (зокрема відмови); пауза; дострокове закриття, якщо ніхто вже не може перебити; пауза 3 с після кожного лота.
- **Секретність:** клієнт отримує лише поточний і завершені лоти, а майбутній і неіснуючий `lot_id` дають однакову відповідь `INVALID_LOT`.
- **Оцінювання:** 10 критеріїв із вагами; функціональні ланцюги (фільтр без джерела води не дає воду); синергії з обмеженням бонусу; штрафи; cap-правила; спільні місця (1, 1, 3); 5 номінацій; пояснення кожного бала.
- **AI-суддя (необов'язковий):** вмикається змінними `OPENAI_API_KEY` і `OPENAI_MODEL`. Він оцінює лише суб'єктивні критерії під анонімними ID; сервер перевіряє схему, діапазони й `evidence_item_ids`. Без ключа працює резервна рубрика з чесною позначкою на екрані результатів. Облік токенів і вартості: `OPENAI_INPUT_RATE`, `OPENAI_CACHED_INPUT_RATE`, `OPENAI_OUTPUT_RATE` (за 1 млн токенів) і `GET /api/admin/usage` із заголовком `X-Admin-Token: $ADMIN_TOKEN`.
- **Результати:** рейтинг, розбір за критеріями, журнал торгів, «А що, якби?» у простому режимі з перевіркою бюджету, реванш, «Поділитися».
- **Надійність:**
  - стан зберігається в `data/state.json` і відновлюється після рестарту, разом із таймерами;
  - захист від CSRF, rate limiting і стандартні коди помилок за Додатком I.

## Теми

Повністю наповнено 4 теми з 15: «П'ять діб в укритті», «Безлюдний острів», «Ідеальний салат», «Валіза для подорожі». У кожній 25–26 предметів, 10 критеріїв, синергії та cap-правила. Решта тем додаються як дані в `aiauction/themes.py`; ядро аукціону змінювати не потрібно. При старті сервер валідує кожну тему.

## Відхилення від ТЗ і чого ще немає

| ТЗ | Тут | Чому / що далі |
|---|---|---|
| Node.js + PostgreSQL + Redis | Python + JSON-файл, один процес | Node на машині не встановлено; рушій ізольований, його можна перенести. Для 100 кімнат × 8 гравців і горизонтального масштабування потрібні PostgreSQL і Redis. |
| WebSocket | Server-Sent Events + REST | Еквівалент для односпрямованих оновлень; кожна подія несе повний стан із версією, тож resync після розриву автоматичний. |
| AI-генерація сценаріїв і лотів | Шаблони з детермінованим вибором за seed | Відповідає рекомендації ТЗ для стандартних тем. Генерація для довільних тем — етап 2. |
| Бібліотека ілюстрацій | Емодзі як `visual_key` | Ліцензовані зображення — окремий етап. |
| Адмінпанель, чат, реакції, історія гравця, офлайн-PWA | Лише `/api/admin/usage` | Наступні ітерації (етап E). |

Віртуальні долари не є грошима й ні на що не конвертуються.
